# 作業終了時の手順

この手順には、目的の違う2種類の確認があります。

- **PCを閉じる前の確認**: ユーザーが「PC閉じる前の確認お願い」と伝えます。アシスタントはその時点のタスクとGitの状態を確認し、保存漏れや未送信の変更など、ユーザーが閉じる前に知っておくとよいことを案内します。自動でコミットやプッシュはしません。
- **作業状態の整理**: ユーザーが「作業状態を整理して」と伝えます。アシスタントはタスク、差分、確認結果、次にやることをまとめます。

コミットとプッシュまで依頼する場合は「PC閉じる前の確認をして、問題なければ今回の変更をコミットしてプッシュして」と伝えます。この言葉を受けたら、毎回あらためて許可を尋ねず、依頼された範囲で進めます。

## PCを閉じる前の基本チェック

1. 開いているファイルを保存する（通常は `Ctrl+S`。VS Codeなら「すべて保存」も使えます）。
2. 実行中の開発サーバーやコマンドがあれば、処理中でないことを確認する。必要ならターミナルで `Ctrl+C` で停止する。
3. 「PC閉じる前の確認お願い」と伝えて、未保存・未コミットの変更や次回の作業を確認する。
4. ローカルに保存されていれば、コミットせずにPCを閉じても作業ファイルは通常残ります。別のPCから続けたい、またはバックアップしておきたい場合はコミットとプッシュを依頼する。

## 作業状態の整理

1. `docs/tasks.md` を更新し、未完了タスクの状態と次にやることを整理する。
2. 変更ファイルと差分を確認し、意図しない変更や秘密情報が含まれていないか見る。
3. 変更に関係する確認を行う。確認していないことは、未確認として報告する。
4. 利用者に見える変更や重要なデータ変更があれば `CHANGELOG.md` を更新する。
5. 作業内容、確認結果、残っているタスクを短くまとめる。

## コミットとプッシュも依頼された場合

1. PCを閉じる前の確認と作業状態の整理を先に行う。
2. 差分に今回の作業以外の変更が混ざっていたら、それらを含めずに進められるか確認する。安全に分けられない場合は、コミット・プッシュせず理由を報告する。
3. 今回の作業分だけを分かりやすいメッセージでコミットする。
4. 現在のブランチと送信先を確認してプッシュする。
5. コミットIDとプッシュ結果を報告する。認証やネットワークの許可が必要な場合は、その時点で依頼する。

## 合図の使い分け

- **「PC閉じる前の確認お願い」**: その時点の状態を確認し、PCを閉じる前に必要なことを案内する。
- **「作業状態を整理して」**: タスク、差分、確認結果、次にやることをまとめる。コミット・プッシュはしない。
- **「PC閉じる前の確認をして、問題なければ今回の変更をコミットしてプッシュして」**: 確認後、今回の作業分をコミットしてプッシュする。
